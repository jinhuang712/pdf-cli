# 044. annotations per page, in a table of their own

Decided: 2026-10-25    Status: current

M1.13 kept a file's annotations in its facts, at most 1,000 links a file, and every read decoded them all. TeX Live's PGF manual holds 44,655 links, so most of its pages showed none, and keeping them all in the facts would have made every read, even of one page, decode a few megabytes. Cache schema 9 adds the table `page_annotation (path, page_index, data, more)`, one row for each page that holds an annotation or has some past its cap: `data` is the page's annotations as JSON, `more` how many the page left out and `why` the caps that did (1,000 links and as many others a page; 100,000 of each kind in a file; 512 KB of text on a page and 32 MB in a file; repeats: an annotation that several pages list is kept once, as the review found 50 pages sharing one array of 2,000 references fill the cache with 37 MB), `words` whether the words under the page's links are read. The table is a rowid table: WITHOUT ROWID took 6.5 MB for 4.4 MB of rows. `pdf read` fetches the rows of the pages in the chunk it reads, and the page says in one line what it left out and why. The words under links are not read with the facts: PDFKit selected them for 44,655 links in 3.6 s, which the first page waited for, and a clock decided which links got words (39,060 or 43,392 of them on two runs). A worker (`__worker words`) reads them for the pages a read shows, once, from the boxes in the rows, and the rows keep them; the count of marks whose words the facts read is fixed (5,000), with no clock. A link to a page of the file with no words under it stands on nothing in the text and repeats a page number the text shows, so it is counted in the page's line, not shown; a link to a web address stays for its address. The facts keep their counts and `moreAnnotations`, and no annotation. The rows go in the same transaction as the file's entry, which deletes the rows of the version before it; `rm`, `clean`, `gc` and `forgetEntry` remove them with the entry (`dropUnused` deletes the rows whose path has no entry). The index checks went to 11, so every file's facts are read again, which fills the table: no migration of rows, as for schema 8.

| Option | For | Against |
|---|---|---|
| **A table keyed by the file's path, one row per page** | The annotations belong to this version of the file, as the facts do: a highlight appended to a file leaves every page key alone. A read decodes the pages it shows. A cap per page keeps a row small. | A second place to clean up with the entry, handled in the one `dropUnused` and in `saveEntry`. |
| Keyed by the page's key | Follows the page-level tables. | An appended highlight changes no page key, so it would never show; and two files that share a page would share links to other pages, which are the file's own (`#p.12`). |
| Keep them in the facts, raise the cap | No new table. | Every read decodes them all: 250 KB at 1,000 links, more than 4 MB at 44,655. |
| Read a page's links when the page is read, from the file | Nothing stored. | Opens the file and PDFKit on every read, and selects the words under each link again. |

A reparse does not touch the rows: they are no result of the page's parse, so there is nothing for it to replace, and the page's links stay as they were.
