# M1.8 — `pdf search` by keyword and with `--regex`

- **Built:** 2026-10-15 in `18c070f`, with review fixes in the commit after it.
- **Written:** 2026-10-15, on the task's branch.

## What was built

- A keyword index of every paragraph, in SQLite's FTS5 with the tokenizer `porter unicode61 remove_diacritics 2`. A page joins it in the transaction that caches the page, and a trigger drops a page's rows with its result. Pages cached before the index join it on the first search of their document. Cache schema 7.
- Chinese and Japanese characters are indexed one by one, split by a thin space that snippets take out, and a query's run of them is a phrase.
- `pdf search <pdf> <words>` and `pdf search <words>` across the library. Every word must share a paragraph; when none does, paragraphs that hold some of them follow, marked.
- `--regex <pattern>` over each file's text, across line, column and page breaks.
- Each hit gives its page, paragraph, section, a flagged page's status and a snippet. `--top`, `--from`, `--budget` with a `next:` line, and `--json`.
- A search of one PDF new to the cache waits up to 10 s for its pages; a library search starts no parse and says what it covered.

## Review

The reviewer built the commit and ran both test scripts. It checked the index against the cache directly in the database: 182 pages and 4,833 paragraphs on 11 PDFs, with no orphan or doubled row, and the counts stayed equal after a `pdf rm` and after a simulated upgrade. It found no input that breaks the query: quotes, `NEAR`, `*`, `text:`, emoji, 3,000 words and 5,000 Chinese characters all worked. It found these:

| # | Finding | Verdict | Resolution |
|---|---|---|---|
| 1 | A pattern with nested repeats, `(\w+\s?)+QQQ`, ran over 60 s on an 11-page paper with no limit; NSRegularExpression has none. | Confirmed | Fixed: the command stops itself after 10 s with an error that names the cause. An end-to-end check plants the pattern. |
| 2 | Copies of one file in the library repeated every pattern hit, and counted as two PDFs; hits were credited to the first path even when that file was gone. | Confirmed | Fixed: one document is searched once, under a path that still exists. |
| 3 | When no paragraph held any of the words, the output still said "these hold some of them". | Confirmed | Fixed: that line shows only when some paragraphs hold some words. |
| 4 | `pdf search nope.pdf` searched the library for "nope pdf", and a first word naming a folder, as `Sources`, became a file search that failed. | Confirmed | Fixed: a lone word ending in ".pdf" is refused with "give the words to find after the PDF"; a folder's name stays a word. |
| 5 | A pattern's count stopped at 10,000 per PDF without saying so. | Confirmed | Fixed: the summary and the JSON say the count stopped. |
| 6 | The first search after the upgrade backfilled every missing page in one transaction, holding the write lock long enough to stall a runner. | Likely | Fixed: 200 pages per transaction. |
| 7 | A cleanup between the backfill's read and its write left index rows with no page behind them, and such a page parsed again never joined the index. | Likely, narrow | Fixed: a page is indexed only while its result is still cached, checked inside the write. |
| 8 | Each hit opened the picks database and read its page alone: 0.93 s to show 1,054 hits across 11 PDFs. | Confirmed | Fixed: one picks database per search, and each file's hit pages read in one pass: 0.37 s. |
| 9 | Snippets lost thin spaces the text holds itself; a pattern's snippet could cut an emoji in half; the budget left out the closing lines. | Likely, cosmetic | Fixed: only the index's own splits go; the context widens to whole characters; the budget keeps room for the closing lines. |
| 10 | The docs named Chinese and Japanese but not Korean, said `--json` gives every hit, and said only new PDFs wait. | Confirmed | Fixed in DESIGNS and FEATURES. |

## Tests

123 unit tests passed, 6 of them new: query quoting, Chinese inside a longer run with a thin space of the text's own kept, the index kept with the cache through a `pdf rm`, the backfill, a pattern across blocks and pages, and a hit's section.
