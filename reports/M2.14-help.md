# M2.14 `--help` that teaches

## Built
- `pdf --help` opens with a "Which command" list (`info`, then `read`, `search` or `crop`; `dump`; `pick` and `transcribe`; the library commands; `agent-guide`) and three examples.
- Every command's `--help` has 2 or 3 complete examples in its discussion; `ls` and `gc` have one, as they take no arguments. The `transcribe` examples use `printf ... |` and `< table.md`, never a heredoc (an indented heredoc does not work when copied).
- `read` and `dump` group their options by purpose in the discussion text. Real `@OptionGroup(title:)` sections were not used: they need every flag moved into a struct. The option list stays flat; flags and parsing are unchanged.
- Only help text changed. The agent guide was not touched.
- Docs: FEATURES.md F13 (examples, and the guide leaves out five flags, not two), ROADMAP.md M2.14 `[x]`, TODO.md (two lines for M2.15). All marked `drafted 2026-10-25`.

## Tests
- New unit test `theHelpTextsNameOnlyFlagsAndCommandsThatParse` in `AgentGuideTests`: every `--flag` a help text names is a flag of that command (any command, for the top level), and every `pdf ...` line in an "Examples:" block parses (25 or more). Renames in M2.16 and M2.17 cannot leave stale help.
- `scripts/test.sh --filter AgentGuideTests`: 13 tests pass. The `--help` of every command was read by hand.
- Not run: the full unit suite and `test-cache.sh` (the user's rule: light tests until the wrap-up).
