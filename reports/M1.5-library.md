# M1.5 — `pdf add`, `pdf ls`, `pdf rm` and `pdf gc`

- **Landed:** 2026-10-15 in `67d2e5c`, with review fixes in `348504d`.
- **Written:** after the fact, on 2026-10-15.

## What was built

- `pdf add` takes files, folders and glob patterns, parses every page, and prints each PDF's ID, title, page count and status. `-j N` raises the worker slots for its runners. `--password` and `--password-stdin` open a locked PDF.
- The library list lives in Application Support. Every read registers its file, writing only when the entry changed.
- `pdf ls` shows each entry's flagged pages, parse progress, a changed file, or a file out of reach.
- `pdf rm` takes a path or an ID and drops only what no other file uses. Picks stay.
- `pdf gc` drops files gone or changed, old parser versions and dead locks, removes library entries of missing files, and compacts the database while no runner is alive.
- The password reaches the runner and workers in their environment, never their command line. It is never stored.
- `testdata/locked/locked.pdf`, password "open sesame", made by `scripts/make-locked-fixture.swift`.
- Cache schema 5.

## Review

The reviewer built the commit, ran the 85 unit tests, and reproduced findings 1 and 2.

| # | Finding | Verdict | Resolution |
|---|---|---|---|
| 1 | A read without the password, after `pdf add --password`, cached "locked by a password" as the result of the file's pages, and `pdf add --password` could not repair it. | Confirmed | Fixed: a missing password fails the file as locked and caches nothing for its pages. A read with the password waits for such a runner, then indexes the file again. |
| 2 | Upgrading the schema deleted every file entry, so a `pdf gc` right after deleted every cached result, OCR included. | Confirmed | Fixed: an upgrade marks entries with older index checks instead of deleting them. |
| 3 | `pdf add --password pw` keeps the password in its own command line while it runs, against the DESIGNS rationale. | Confirmed | Fixed: `--password-stdin`, and the docs state the exposure of `--password`. |
| 4 | `pdf gc` checked a file's stat outside its write, so it could delete an entry a runner had just re-indexed. | Likely | Fixed: it deletes only while the entry holds the stat it read. |
| 5 | Results for unreadable pages were saved before their document, so a concurrent cleanup could drop them. | Likely | Fixed: they save in the same transaction as the document. |
| 6 | Compacting held the write lock through VACUUM, so runners silently lost writes. | Likely | Fixed: `pdf gc` compacts only while no runner is alive. |
| 7 | `pdf gc` removed library entries for files on an unplugged drive. | Likely, design | Fixed: a file on an unmounted volume counts as out of reach, and `pdf ls` says so. |
| 8 | `pdf add` de-duplicated paths in O(n²) resolutions. | Confirmed | Fixed: a set. |
| 9 | `pdf ls` judges every cached page on every run: fine for tens of PDFs, slow for thousands. | Likely, performance | **Not fixed.** Logged in TODO. |
| 10 | Smaller: a password-retry race; glob matches not filtered to PDFs; symlinked PDFs skipped in folders; DESIGNS said IDs are 8 digits where `rm` takes any prefix of 4 or more; the gc test passed on the WAL truncation alone. | Mixed | Fixed: the race (finding 1's wait), patterns and links, the ID doc, and a test that proves compacting shrinks the file. |
