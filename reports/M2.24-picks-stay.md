# M2.24: a reparse never deletes picks

- **Landed:** 2026-10-25, built in `48d3ca8`, with the review's fixes after it.
- **Versions:** parser version 19, page key 2, index checks 10 and cache schema 8 are unchanged. The picks' table (in `library.sqlite`, not the cache) changed its key, see M1.

## What was built

- The user chose option A of M2.23's open question: a reparse never deletes a pick. `Picks.reconcile` (read, judge, delete) became `Picks.tally`, read-only, opened with `Picks(readOnly: true)`. The runner prints one `picks` line for each page key; `picks-failed` and the exit 1 it caused are gone.
- `--json`: `picksApply` and `picksStale` replaced `picksKept` and `picksCleared` (nothing is cleared, so the old pair would lie); `picksUnknown` replaced `picksFailed`; `libraryFailed` is new. Text: `2 picks still apply · 1 stored pick does not apply`. Tally by page key and the file-swap totals from M2.23 stay.
- An OCR round trip is lossless: `reparse --step ocr` leaves the pick stored and ignored, a plain `reparse` brings the readings back and the pick applies.
- Docs: FEATURES F8, F10 (and its Gap), DESIGNS reparse decision (revision note, options table), `reparse --help`, the guide line ("Deletes no picks."), ROADMAP tick, TODO.
