# M2.26 `pdf search` reads stored edge summaries; `pdf dump --refs` writes link DOIs

## Built
1. **Edge summary.** Table `search_edge (page_key, parser_version, data)` holds each page's `Furniture.Summary` (label and the few edge candidates, with an `arXiv` flag and a version `v`) as JSON, "-" for a page with no layer. `Store.insertResult` writes it in the transaction that indexes the page; trigger `page_result_leaves_the_edges` deletes it with the result, so a reparse, `rm`, `gc` and a parser-version change replace or remove it. `Search.judge` judges from summaries; `Furniture.find` on layers builds summaries and calls the same function, so `read` and `search` agree. A page with no row gets its summary made on the first search that needs it. A pattern search still judges its decoded layers.
2. **`dump --refs` DOIs.** `ReferenceIndex.allEntries` takes the `links` closure of `lookup` (shared `linkedDOI`); `references.json` has the DOIs from links. `read` uses `entryCount`.
3. **Versions.** Summary version 1 (`Furniture.summaryVersion`), in CLAUDE.md's Versions line. Index checks stay 11, schema 9.

Hits and counts, default and `--show headers`, are byte-identical (md5) to the build before for "the", "chapter", "figure". The summaries take about 90 KB for the manual, against 4.7 MB of results. (M2.22 measured 0.91 s before this change on the same file; this run's 0.60 s is the same build on a quieter machine.)

## Review findings (Opus) and resolutions
| # | Finding | Resolution |
|---|---|---|
| H | An existing schema-9 cache never got the table: `createSchema` returns early at version 9, so search failed with "no such table", read and reparse "stopped before it finished", and doctor said nothing. | `createEdgeSummaries` (table and trigger, `IF NOT EXISTS`) runs on every open, outside the guard. Chosen over schema 10: it needs no migration of every cache and two builds sharing a cache do not fight over the version. Test `aCacheMadeBeforeTheTableGetsTheTableWhenItOpens` (drops table and trigger, reopens, saves, searches, deletes); checked by hand on the release build. `pdf doctor` is not changed: the state cannot persist any more, as the next open repairs it. |
| M1 | `isNew` was read after the summary insert, which always changes a row, so the index-once guard was gone and concurrent searches indexed blocks twice; the hunk also held the DDL and the insert twice. | `isNew` is read right after the `search_page` insert; duplicates removed. Test `aPageIsIndexedOnceWhateverTheOrder`; script `testdata/scripts/index-race.sh` (two concurrent searches on an emptied index): rows equal distinct blocks in 3 tries. |
| M2 | A stale or undecodable summary was never rebuilt; search disagreed with read. | Summaries carry version `v`; a row of another version or one that does not decode is missing, made again and replaced (`INSERT OR REPLACE`). ## Limits
- A summary stays in force until its page's result changes or the summary version is raised; whoever changes a rule in `Furniture.edges`, `key`, `pageNumber` or the arXiv pattern must raise it.
- The review's tests for the table and the index-once guard were not run against the build before the fix, as they were found there by the reviewer's own repro.
