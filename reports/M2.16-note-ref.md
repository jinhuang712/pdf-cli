# M2.16 `pdf note` and `pdf ref`

## Built
- `pdf note <pdf> 7` and `pdf ref <pdf> 12` (`Sources/pdf/Lookup.swift`) hold the look-up code that was `ReadCommand.footnote` and `.reference`. They behave as the flags did: whole document parsed first, provisional mark, not paged, not held to the budget. They take `--json` and nothing else (the flags took no password option).
- A look-up that matches nothing, or is ambiguous, is a failure in the contract's shape, exit 1, JSON on stdout, listing the ids that exist (M2.15 review, M4). Same for `read --section`, `--printed-page` and a `--from` page outside the pages read.
- `read --footnote` and `--ref` are removed; as hidden options they end 64 with a pointer to the new command and run nothing.
- Updated: output hints, `pdf info` lines, the agent guide (under 2,000 tokens), help texts, `pdf --help`, FEATURES.md, DESIGNS.md, README.md, plan/ROADMAP.md, `scripts/test-cache.sh` (not run). The cache holds no hint text, so no version changes.
