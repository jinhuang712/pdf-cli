# M1.12 — The smoke set and the safety set

- **Built:** 2026-10-17, on the task's branch.
- **Written:** 2026-10-17, on the task's branch.

## What was built

- **The smoke set** was already there: `testdata/smoke`, 10 arXiv papers under CC BY 4.0 and a 1951 NACA report scanned with an old OCR layer, public domain, gathered for M0.2 with their sources and licences in `testdata/smoke/SOURCES.md`. Unit tests and `scripts/test-cache.sh` read parts of it; nothing read every file whole. `scripts/smoke-check.sh` now does, with an empty cache: each file must exit 0, or 2 for flagged pages with the rest valid, print a heading for every page, and finish within 300 s.
- **The safety set** is new: `testdata/safety`, 20 files, 820 KB, all written by hand by `scripts/make-hidden-fixture.swift`, so each trick is exactly the drawing command it names:
  - 8 hidden-text files, one per trick the roadmap names: text in the background's color, tiny, clipped, covered by an image, covered by a white box, off the page, in a layer switched off, and in the invisible render mode. Each is a page of `testdata/hidden/hidden.pdf` as a file of its own: visible lines, and one planted line that starts "PLANTED".
  - 2 visible controls: white text on a dark box, and a scan's image under an invisible text layer that spells the words it shows. Both must read as text.
  - 5 files that carry what a reader sees beside the text: comments (a sticky note by "Reviewer 2" with its popup, a highlight with a comment, a note typed on the page), form fields (a filled text field, a checked box, a choice and an empty field), a link to a web page, attachments (one in the document's name tree, one on the page), and scripts (JavaScript on opening the document and the page, and a link that launches a program).
  - 5 broken files: not a PDF, empty, cut short at 60%, a cross-reference table that marks every object free, and a page whose content stream is not what its filter says.
- `scripts/safety-check.sh` runs the set, with a 120-second limit on each command, and checks:
  - every hidden-text file and every planted line of `hidden.pdf` (69 pages, 44 planted lines): the planted words stay out of normal output, a hidden-text marker stands in their place, and `--include-hidden` shows them labelled;
  - the visible controls read with no marker;
  - `pdf info` names the comments, highlights, form fields, attachments and scripts the files carry;
  - each broken file, and `testdata/hidden/broken.pdf`, ends with an exit of the tool's own, not a crash or the limit, and an exit of 3 says why.

  It ends with goal G16's line: "G16: 52 of 52 planted hidden texts flagged and kept out of normal output; 0 crashes or hangs". `scripts/test-cache.sh` runs both scripts and checks their last lines.

## What the safety set found

A page whose content stream does not decode read as an empty page that was fine: "flagged: none", exit 0. CGPDF draws nothing of such a stream, and its scanner reports success, so neither the text nor the image showed anything missing. The fix:

- `FontCheck`, which already scans each page, marks the page damaged when one of its content streams declares 64 bytes or more and decodes to none. An empty stream, compressed, takes a few bytes, ASCII85 and Flate together about 20, so a stream that long held something its filter could not give back.
- The page is low-quality: a failure block after its blocks says "part of the page's drawing commands is damaged and could not be read, so what it draws is missing here and from the page's image". It names no command, since the image lacks it too; the agent guide says to tell the user. The text the page's other streams draw reads as before.
- Parser version 11, so cached pages are parsed again.
- Not caught: a stream damaged partway, which decodes in part, and a damaged form drawn from the page. FEATURES.md → F8 says so.

The check costs nothing measurable: `FontCheck` over the smoke set's 182 pages took 0.12 s in all, with the decoding. It marks no page of the smoke set, the hidden-text fixtures or the OCR samples.

## What the sets do not check yet

- Where comments, highlights, form fields and links sit in the text: that is M1.13, and `carries-*.pdf` are its fixtures. Today the safety check asks only `pdf info` for their counts, and only that `carries-links.pdf` reads.
- G17, that every object reaches the output as text or a marker, needs a script that lists every object PDFKit and Core Graphics report; that comes with M1's goal measurement, after M1.14 marks images and drawings.
- The goals measured on the open test set (G2, G4, G9, G12, G13): the open test set is M2.1. M1's measurement runs on a local set of open-access PDFs that stays out of the repo, as the user decided on 2026-10-16.
