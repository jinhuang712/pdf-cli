# M1.12 — The smoke set and the safety set

- **Built:** 2026-10-17, on the task's branch.
- **Written:** 2026-10-17, on the task's branch.

## What was built

- **The smoke set** was already there: `testdata/smoke`, 10 arXiv papers under CC BY 4.0 and a 1951 NACA report scanned with an old OCR layer, public domain, gathered for M0.2 with their sources and licences in `testdata/smoke/SOURCES.md`. Unit tests and `scripts/test-cache.sh` read parts of it; nothing read every file whole. `scripts/smoke-check.sh` now does, with an empty cache: each file must exit 0, or 2 for flagged pages with the rest valid, print a heading for every page, finish within 300 s, and flag the pages `testdata/smoke/expected-flags.tsv` lists, no others; a page that fails fails the file. `--write` writes that list from a run, when a change to the parse means to change the flags.
- **The safety set** is new: `testdata/safety`, 20 files, 836 KB, all written by hand by `scripts/make-hidden-fixture.swift`, so each trick is exactly the drawing command it names:
  - 8 hidden-text files, one per trick the roadmap names: text in the background's color, tiny, clipped, covered by an image, covered by a white box, off the page, in a layer switched off, and in the invisible render mode. Each is a page of `testdata/hidden/hidden.pdf` as a file of its own: visible lines, and one planted line that starts "PLANTED".
  - 2 visible controls: white text on a dark box, and a page-size image under a text layer in the invisible mode, as a scan's own layer lies. The image is a grey texture that shows no words: the file holds the tool to its rule that such a layer reads as text (FEATURES.md → F9 → Gap). Both must read as text.
  - 5 files that carry what a reader sees beside the text: comments (a sticky note by "Reviewer 2" with its popup, a highlight with a comment, a note typed on the page), form fields (a filled text field, a checked box, a choice and an empty field), a link to a web page, attachments (one in the document's name tree, one on the page), and scripts (JavaScript on opening the document and the page, and a link that launches a program).
  - 5 broken files: not a PDF, empty, cut short at 60%, a cross-reference table that marks every object free, and a page whose content stream is not what its filter says.
- `scripts/safety-check.sh` runs the set, with a 120-second limit on each command, and checks:
  - every planted string, as the generator lists them in `testdata/safety/planted.tsv`, not as the tool's output shows them: 61 strings, 52 on the 48 pages of `hidden.pdf` that hide text and 9 in the safety set's files. Each word of a planted string that its page shows nowhere else must stay out of the page's text in normal output, the page must mark hidden text, and `--include-hidden` must show it. A page not named "visible" whose hidden text the generator cannot name stops the generator, so no planted string drops out of the count;
  - the visible controls read whole: exit 0, no marker and no failure block;
  - `pdf info` names the comments, highlights, form fields, attachments and scripts the files carry;
  - each broken file, and `testdata/hidden/broken.pdf`, ends with an exit of the tool's own and a reason for an exit of 3;
  - in every file, a command stopped by a signal or the limit, and a reader that crashed, ran out of time or memory, or stopped while opening the file, count as a crash or a hang.

  It ends with goal G16's line: "G16: 61 of 61 planted hidden texts flagged and kept out of normal output; 0 crashes or hangs". `scripts/test-cache.sh` runs both scripts and checks their last lines.

## What the safety set found

A page whose content stream does not decode read as an empty page that was fine: "flagged: none", exit 0. CGPDF draws nothing of such a stream, and its scanner reports success, so neither the text nor the image showed anything missing. The fix:

- `FontCheck`, which already scans each page, marks the page damaged when one of its content streams declares 64 bytes or more and holds no operator. An empty stream, compressed, takes a few bytes, ASCII85 and Flate together about 20, so a stream that long held something its filter could not give back. Each stream is scanned, not copied out.
- The page is low-quality: a failure block after its blocks says "part of the page's drawing commands is damaged and could not be read, so what it draws is missing here and from the page's image". It names no command, since the image lacks it too; the agent guide says to tell the user. The text the page's other streams draw reads as before.
- Parser version 11, so cached pages are parsed again.
- Not caught: a stream damaged partway, which still gives operators, a damaged form drawn from the page, a stream whose length is missing or no number, and the streams of a page with no resources. FEATURES.md → F8 says so.

The check costs little: the reviewer timed a full scan of every stream at 24 s over 177,512 pages of TeX Live's documentation, 0.14 ms a page. It marks no page of the smoke set, the hidden-text fixtures or the OCR samples.
