# M3.6 — First question runs (small, Haiku 5.5)

Date 2026-10-29. Not the final M3.6: the 200-question set and the 60-file open test set (M2.1, M2.2) do not exist yet. This is the small version that [MEASURE.md](../MEASURE.md) describes, to see early where G1, G5 and G15 stand and what costs what.

## What was run

- Model `claude-haiku-5-5`, `claude -p`, a new session and a new `PDF_CLI_HOME` for every run, one run per question per arm.
- Arm A: `Bash` + `Read`, the agent guide appended. Arm B: the built-in `Read` only. (A first A run had `Bash` only; the agent could not look at a crop, which is not how the tool is used, so A has `Read` since.)
- Questions and scripts: `testdata/eval/`. Run logs: the main checkout's `private/eval/2026-10-29/` (not committed).

| Set | File | Questions |
|---|---|---|
| attention | Attention Is All You Need, 15 pages | 8: text 2, table 3, equation 1, footnote 1, no answer 1 |
| nist-lookup | NIST SP 800-53 Rev. 5, 492 pages | 8: table 1, text 1, footnote 1, control titles 4, no answer 1 |
| nist-table | the same file | 6: cells and counts in the appendix tables, one figure |

Answers were checked against `pdftotext` of the file, not by eye.

## Results

All 22 questions were answered right in both arms (page numbers aside, see findings).

| Set | A cost | B cost | A ÷ B | Median of the per-question ratios |
|---|---|---|---|---|
| attention, first build | $0.0172 | $0.0265 | 65% | 0.64 |
| attention, after the fixes below | $0.0136 | $0.0265 | 51% | — |
| nist-lookup | $0.0106 | $0.0642 | **16.5%** | 0.15 |
| nist-table | $0.0223 | $0.0405 | **55%** | 0.67 |

Estimated cost shares (prices assumed in the usual ratios, fit error about 9%; Haiku 5.5's price list was not looked up): A about 52% cache write, 25% cache read, 23% output; B about 85%, 6%, 9%. The cache here is the model's prompt cache, not pdf-cli's.

## Findings

| # | Finding | Resolution |

| 2 | `pdf read --json` at the default budget printed 28,465 characters on a 15-page paper, 1,500 under the line | Fixed (4f9e5bd): `--json` counts 0.7 of the budget in `read`, 0.5 in `search`; the same paper prints 20,401 |
| 3 | Agents read 20,000 characters when they wanted one table (`--from` at the default budget); two questions cost more than reading directly | The guide names `--budget 800` for one passage; the two questions fell from $0.0038 and $0.0033 to $0.0013 and $0.0015 |
| 4 | **Big tables are the weak spot.** The appendix table C-18 count took 12 turns and 11 tool calls, more than direct reading. A table is a crop, not text; "count the rows that…" needs the whole table | The user, 2026-10-29: whatever is not plain text goes to the model as it is (the crop); no table-text view or row search is built. Stays a known limit of big tables, to go in FEATURES.md's Gaps |

## What this says about the goals

- **G1 (≤ 20% of the tokens):** met on look-ups in a long file, missed on table questions (55%) and on a short file (51%). The saving grows with the file's length, because direct reading grows and a look-up does not. Whether the whole question set passes depends on its share of table questions.
- **G5 (answers):** equal here, every question right in both arms. Too few and too easy for more.
- **G15 (commands):** no failed `pdf` command in the final A runs; the table question shows many calls that were wasted, which G15 does not count.

## Limits

One run per question, one model, two files, questions that favour a search tool. Treat the numbers as a trend. The cost shares are estimates. The questions were not drawn blind to the tool.

Unit tests (`scripts/test.sh`) pass after the fix, 0 failures; `theGuideStaysCompact` needed two words cut elsewhere in the guide. The end-to-end check (`test-cache.sh`) was not run. No reviewer has seen the code change yet.
