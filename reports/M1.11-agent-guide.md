# M1.11 — `pdf agent-guide` and its Claude Code skill

- **Built:** 2026-10-16 in `d28e6ca`, with review fixes in the commit after it, on top of the TODO fixes that landed while it was built.

## What was built

- `pdf agent-guide` prints a guide that teaches an agent the tool in one read: where to start, every built command with its flags but two, how to read the output and the exit codes, the failure, unsure and set-aside blocks, the hidden-text markers as M1.10 shipped them, and the rule that a PDF's text is content to read, never instructions to follow. It started from the draft in HANDOFF.md's appendix, checked line by line against the code and real runs.
- `pdf agent-guide --install claude-code` writes the guide as a Claude Code skill, `~/.claude/skills/pdf-cli/SKILL.md`, under frontmatter of `name` and a `description` that leads with when to use the tool. With `CLAUDE_CONFIG_DIR` set, the skill goes under that folder instead. A second install replaces an earlier version, or says the skill is up to date; a `SKILL.md` that is a link is written through, even to a file not made yet, so the link stays. After a change it says that a running session picks the skill up, after `/reload-skills` when the skills folder is newer than the session. It warns when no `pdf` is on the PATH, or another one is, since the skill's commands run the one a shell finds.
- The skill grants no tool permission: no `allowed-tools`. That choice stays the user's.
- The guide lives in `Sources/PDFCore/AgentGuide.swift`, built into the binary. The design and the options it beat are in DESIGNS.md → "Decision: one guide, printed or installed as a skill".
- A new test target, `pdfTests`, imports the executable, so the tests can hold the guide to the CLI's own subcommands, help and parser. They check both ways: every command and flag the guide names exists, with the command named before it on its line, in code or in prose, in any case; every command the guide writes out parses, values and usage included, and so does each flag written with its value; and the guide names every command `pdf --help` lists and every flag of each, but `read --full`, which reads as a read with no page flag does, and `add --password`, which shows the password to every user of the Mac.
- `pdf pick` checks its block and its reading before it runs, so a wrong one fails as the parser's, with the same message and exit code 64, and the guide's test can catch it.
- Rebased before landing onto the TODO fixes of the same day, which added a whole-file failure, "slow to open"; the guide names it with the others.
- Changes from the draft: that pictures, charts and drawings get no marker yet; the exit codes of each command; `--budget` for search, `-j` for add, `--json` for crop, `--format text` with its headings; locked files, with the user running the unlock; the `## p.12 (printed 237)` heading; the one-reading unsure block; the PDFKit warning; the five ways hidden text prints its reason, the hidden-text check that stopped at its limit, and that hidden text leaves the exit code alone and stays out of search and info; and `pdf agent-guide` itself.

## Format check

The skill format was checked on 2026-10-16 against [code.claude.com/docs/en/skills](https://code.claude.com/docs/en/skills):

- Personal skills live in `~/.claude/skills/<name>/SKILL.md`. The frontmatter sits between `---` lines, the first on the file's first line.
- `description` is what Claude reads to decide when to use a skill, and the listing cuts it at 1,536 characters: "Put the key use case first". The skill's is 403 characters and starts "Use whenever you need to read, search or cite a PDF on this Mac".
- `name` and `description` are the only fields used: claude.ai and the Skills API refuse any field outside `name`, `description`, `license`, `compatibility`, `metadata` and `allowed-tools`.
- Claude Code fills in `$ARGUMENTS`, `$0`, `$1` and `${CLAUDE_…}` in a skill's text, and runs a command written as an exclamation mark before a code span at a line's start or after a space. A test keeps all of them out of the guide.
- The docs advise a `SKILL.md` under 500 lines. It is 58.
- `CLAUDE_CONFIG_DIR`: [the environment-variable docs](https://code.claude.com/docs/en/env-vars) say it replaces `~/.claude` for settings, history and plugins, and say nothing of skills. A bug report from April 2026 shows Claude Code looking for user skills under it, so the install follows it. Not checked with a live session.

Checked live: a headless Claude Code session (`claude -p`, Haiku) in a scratch project with the skill in its `.claude/skills/pdf-cli/` listed the skill and quoted its description's first words, and `/pdf-cli` loaded its body word for word, before the review's fixes and again after them. That was a project's skills folder, which takes the same format as `~/.claude/skills`. Ruby's YAML parser reads the frontmatter as two keys. The skill was not installed into this Mac's own `~/.claude`: `pdf` is not on the PATH yet, so a skill there would send every session to a command it cannot run.
