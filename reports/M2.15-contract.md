## Built
- `Sources/pdf/Contract.swift`: `Contract.fail` (prints a failure in the one shape and returns the exit code), `Contract.guarding` (runs a command's body; anything it throws that is not ArgumentParser's own, an `ExitCode`, a `ValidationError` or `CleanExit`, becomes a failure line and exit 1; a missing file reads `no such file`), `Contract.json`. Every command's `run()` is now a call to `guarding` around its old body.
- `--json` on `add`, `ls`, `rm`, `gc`, `pick`, `transcribe`, `agent-guide` (with `--install` too). Outputs are listed in FEATURES.md F7.
- Exit codes: a missing file is 1 and a file that does not open is 3 on every command that takes a file. `DumpError` says whether it is the file or the folder (`fileFailed`), so a folder that cannot be written is 1. `add` of several paths: 2 on a mix, 3 when all failed and one failed to open, 1 when none could be tried.
- `gc`: the line says "compacted the cache, freed X" and, when it removed nothing, "the space that earlier pdf rm calls left"; with a parse running there is no size. JSON has `freedBytes` and `compacted`.
- `dump`: the output folder has every link above it resolved (the folder itself is left as given, so the refusal of a link still works), so text and JSON print one form, `/private/tmp/…`. Its JSON is one compact line like the others.
- Guide: the exit-code bullet is one line that also says every command takes `--json`; `--json` is in the test's `everywhere` set. Help: the top-level help says it; `add`, `rm`, `pick`, `transcribe`, `ls`, `gc` and `agent-guide` show a `--json` example.
- Docs: FEATURES.md F1, F6, F7 (Gap shrunk), F8, F11, F13; ROADMAP.md `[x]`; TODO.md (the two items go).
