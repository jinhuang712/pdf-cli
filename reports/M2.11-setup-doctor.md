# M2.11: `pdf setup`, `pdf doctor`, and `pdf gc` into `pdf doctor --clean`

Landed 2026-10-25. Machine: an M3 with 6 performance cores, macOS 26.

## What was built

- **`pdf doctor`** (F12): the macOS version and what a newer one unlocks (only what the code does: the scan reader before macOS 26, OCR languages and detection before 13), the parser version, models (none exist), cache and library sizes and counts, the parsing settings in force with their sources, runners and slot use, what is missing, and problems. It changes nothing and ends 0. States the next normal command repairs (older schema, log files gone, a cut-off run) are `notes`; problems are what only the user can fix.
- **`pdf doctor --clean`** does what `pdf gc` did, and removes leftover runner locks; `--dry-run` opens both databases read-only and counts (M2.18's rules). `pdf gc` is a hidden stub that ends 64 with "`pdf gc` is now `pdf doctor --clean`". Old and new clean were compared on several homes by the reviewer: identical.
- **`pdf setup`**: `--memory light|balanced|fastest|<size>|default`; asks only at a terminal; lists models to download (none; a `ModelSpec` list, a notice template, no download code).
- **Settings:** `settings.json` in `~/Library/Application Support/pdf-cli/`, read once per process by `Env.parsing`, with the sources shown by doctor. `PDF_CLI_WORKERS` and `PDF_CLI_MEMORY_LIMIT_MB` still override; `PDF_CLI_PRESSURE` plants pressure for tests.
- **Pool:** the budget makes the worker count (budget over 2 GB, at least 1, at most the greater of 2 and the performance cores) and each worker's limit (2 GB, or the budget when smaller). Already there: the shared `flock` pool, slot 0 kept for waited-on pages, promotion of background workers. Built here: the budget, fewer workers under memory pressure, heat or Low Power Mode, OCR and space-repaired files running half as many workers (never under two where the pool has two), and the yield rule below.

## Design choices (DESIGNS.md → "Decision: parsing's memory in `settings.json`, and `doctor --clean`")

Name `--clean` (beat `doctor clean` and `--fix`); the setting in Application Support (beat `UserDefaults` and the Caches folder). After the review: presets are worker counts shown as memory for this Mac, so `balanced` is exactly the unset default and the default is never above `fastest`.

## Versions

None changed: parser version 19, page key 2, index checks 10, cache schema 8. Nothing here alters what a parse produces or what a key hashes. The pool, the settings and the clean touch no result.

## Review findings and resolutions

| # | Finding | Resolution |
|---|---|---|
| H1 (high) | With a pool of one slot (`light`, a budget under 4 GB, or pressure) background runners retook slot 0, so a waited-on page queued behind background parses: 38.8 s for the reviewer. | A command that fails to get a slot leaves a heartbeat file in the pool folder (0.5 s window). In a pool of one, background work takes slot 0 only while no such mark is fresh, and a runner stops a background worker that holds it (kind `yielded`; its pages go back in line with no try counted). Measured on the release build with the reviewer's method (page 1 of the NACA scan, then page 1 of another new paper): the commit before the fix gave 30.8 s with `light` and 16.2 s with `light` plus `PDF_CLI_PRESSURE=high`; the fix gives 0.77-0.83 s for unset, light, balanced, and light plus pressure, 0.58 s for fastest. (A first run of a fresh binary took 13.7 s, a cold start that did not repeat.) The "behaves as before" claim in DESIGNS is reworded: the pool is what it was, but the pressure rule and the OCR halving hold for every Mac. Tests: `WorkerPoolTests` pins the pool-of-one rule. |
| M1 | `pdf add -j N` could exceed the user's budget; doctor counted only slots up to the worker count. | `-j` is capped at the plan's worker count and its help and F1 say so; the guide no longer teaches `-j` (left out in `AgentGuideTests` with the reason). Doctor counts every slot file. |
| M2 | Crash on huge sizes in `settings.json` (Int64 shift, overflow in the warning). | Sizes are 512 MB to 1 TB; `TB` is accepted; hex, exponent and signed forms are refused; a file outside the range is a problem and the defaults hold; the memory limit is clamped before the shift. Tests feed 1e19, 4611686018427387904 and 9223372036854775807 through `setup` and `doctor` by CLI. |
| M3 | `--clean` treated a stopped runner's lock as left over (5 s heartbeat) and could compact under it. | A lock is held while its process exists and its heartbeat is under ten minutes old; leftover locks are decided before any delete; compaction waits on any held lock. A test SIGSTOPs a `sleep` and checks its lock stays and the cache is not compacted. |
| M4 | Presets could put the unset default above `fastest`; prompt said "up to N workers". | Presets are 1 worker, the default, and a worker per performance core (at least 2); the prompt says the count. |
| M5 | Doctor ended 2 on self-repairing states. | Doctor ends 0 and lists problems; self-repairing states are notes; `--clean` ends as the clean did. F8, F12 and the guide agree. |
| L1 | JSON keys missing when unset. | `Nullable` encodes null; tests check every key. The `&&`/`\|\|` test line is rewritten. |
| L2 | "a parse is running" on a home with no cache. | `parseRunning` is its own key, true only when compaction waited. |
| L3 | Wrong hints. | A dry run on an older schema says to run `pdf ls`; the `--dry-run` hint appears only when the cache opens; a corrupt cache or library gets a next step. |
| L4 | An unreadable settings file or Support folder was "not set". | Only not-found means not set; the rest are problems. |
| L5 | `1TB` refused; doctor and setup used different units. | One formatter, `Settings.format`, binary units. |
| L6 | A symlinked `settings.json` was replaced. | Written through; `--memory default` writes `{}` through a link rather than deleting it; documented in F12. |
| L7 | Docs. | DESIGNS reworded (urgency, "at least 1", OCR halving including space repair); the guide no longer implies `doctor --dry-run` alone works. |
| L8 | Test raced a runner. | `settle` added before the clean. |
| L9 | The guide's "Reading the output" had 8 leading spaces, so Markdown showed it as code. | Indentation fixed; the guide stays under 2,000 tokens. |

Limits kept (not review findings): the OCR weighting is per runner, not across the pool; a yielding background worker loses the page in progress.
