# M2.21 Limits on big files

## Built
1. **Content-stream bomb.** A content stream of 600 KB that inflates to 600 MB (the review's `bomb-600.pdf`, remade as `testdata/safety/broken-content-bomb.pdf` by `scripts/make-hidden-fixture.swift`) took 45 s and 1,221 MB. The holder was not the drawing: the page key copied every content stream with `CGPDFStreamCopyData` (15 s and 1.2 GB at the index), and the sample check read the page's text through PDFKit (14 s). `StreamGuard` counts a content stream's operators with CGPDFScanner, which reads as it goes and holds nothing, and stops past 20 million. A page over the limit fails at once ("too many drawing commands to read: …") with the crop command; its key hashes the stream's dictionary and the limit, not its bytes; the index, the sample check and the parse skip it. Other pages keep their keys, so the page key version stays 2. plan/decisions/052-a-content-stream-is-counted-by-its-operators-before-anything.md → Decision: a content stream is counted by its operators before anything copies it" has the options it beat.
2. **Grid join.** `Drawing.join` is the old join (each piece joins the first earlier group it is close to, pass after pass) with the neighbours found through a 32 by 32 grid. A union-find was tried first and rejected: the side-by-side join compares heights, so the order of joins shows in the groups (it differed from the old join on 120 of 300 random pages).
3. **`pdf crop --figure/--table/--equation`** parses the unparsed pages in batches of 40 from the start, stops at the first batch that holds the number, or at 60 s with "no figure 7 found yet: stopped at the time limit of 60 s with N of M pages searched; run the command again …". Exit codes and the failure shape are as before.
4. **`pdf reparse`** replaces its pages in chunks of 50, each in one transaction. A killed run keeps its finished chunks; no chunk starts after 90 s; the run ends 2 with the pages left and the command for them (`--json`: `remaining`, `next`, `stopped`). DESIGNS.md's decision is retitled "… in one transaction per chunk", with a dated note.

Test hooks (undocumented, like `PDF_CLI_PAGE_TIME_LIMIT`): `PDF_CLI_LOOK_BATCH`, `PDF_CLI_LOOK_TIME_LIMIT`, `PDF_CLI_REPARSE_CHUNK`, `PDF_CLI_REPARSE_TIME_LIMIT`.

## Measurements (release build, `/usr/bin/ps` RSS sampled every 0.2 s)
| Case | Before | After |
|---|---|---|
| `read --page 2` of the bomb | 45 s, 1,221 MB, "time limit" | 1.2 s, 20 MB |
| the same under `PDF_CLI_MEMORY_LIMIT_MB=400` | fails by memory | 0.7 s, 20 MB |
| `pdf info` of the bomb file | 15 s, 1,215 MB | 0.5 s, 20 MB |
| two Flate filters in an array (≈1 KB stored) | 52 s, 1,221 MB | 1.7 s, 18 MB |
| Type 3 glyph procedure of 600 MB | 51 s, 1,227 MB | 0.9 s, 18 MB |
| 2,000 overlapping bands, entries looked at in the grid | 713 and 1,855 million (with the copies the review found) | at most 2 million |
| `read --budget all` of the 11 smoke files, old vs new | | identical, but where reference links and an OCR score vary from run to run on the old build too (links are judged against the pages parsed so far) |

The review's 80-stroke spiral (6.4 s) is gone; the cost model (n²/2 comparisons a pass) is measured by counting comparisons: on 2,000 bars the old join makes over a million, the grid under 50,000.

## Review findings (Opus: 1 high, 4 medium, 9 low)
| # | Finding | Resolution |
|---|---|---|
| H1 | A refusal was lost on later pages that share the form through a resources dictionary already hashed (one keyer serves a whole job) | The keyer counts refusals and remembers every container that held one (`refusals`, `refusalsBefore` in `finish`). Test: two pages sharing a form of 5,000 operators, one keyer, limit 1,000; fails before. |
| M1 | The grid appended a grown group to every cell of its new region: O(cells × n²) on large overlapping shapes | A grown group is added to its newly covered cells only. Test counts grid entries looked at (2 million at most; 713 and 1,855 million before). The unmeasured "milliseconds" comment is gone; the 2,000-shape page test (passed on the old code) no longer claims a speed. |
| M2 | `crop --figure` lost the ambiguity check; one command, two answers as the parse went on | When it finds the number before the whole file is parsed, the output says `not searched: N pages (6-18) …` and `--json` has `notSearched`; FEATURES updated. Tests (text, JSON) fail before. The "same paper twice" file was not rebuilt: the tests use the 18-page paper with a batch of 4. |
| M3 | The "130 MB" bound holds for one filter only; glyph procedures and patterns copied unchecked | Only streams with no expanding filter, or one Flate or RunLength filter (ASCII filters only shrink), skip the count. Type 3 glyph procedures and tiling patterns are counted. Fixture `broken-content-bomb-more.pdf` (filter array, glyph bomb); measured above; tests fail before. A capped streaming inflate was not built: CGPDF gives no raw bytes. The few-operators bomb stays the recorded gap (FEATURES, DESIGNS). |
| M4 | `reparse --json` printed progress on stderr before the object | No progress under `--json`; test fails before. |
| L1 | Possible endless loop in the crop batches | The read's outcome is checked, a batch that adds no page ends the loop, the time check no longer needs `parsed < keys.count`. Not tested: no way to make a read add nothing. |
| L2 | A runner error after some chunks were replaced said nothing of them | Returns the chunks done with `stopped` and the pages left, ends 2, and the command clears the picks of the pages replaced. Not tested: no way to make the runner fail between chunks. |
| L3 | Two concurrent reparses used up the busy-wait budget | The busy and failure counts reset after each chunk. Not tested (needs two reparses of one file in step). |
| L4 | `next` dropped the password | `--password-stdin` whenever any password was given; test fails before. |
| L5 | Overrun by one step; `Int(inf)` traps; 0.5 prints as 0 | FEATURES says a batch or chunk that began before the limit ends (still under 120 s); a limit that is not a finite number of seconds, 0 or more, is the default; under 1 s prints one decimal (tests expect "0.0 s"). |
| L6 | Refused pages could share a key and the docs said the limit is hashed | The limit is hashed now, as DESIGNS says. Two refused streams with one dictionary share a key and one failure; recorded in the commit message. The page key version is not raised. |
| L7 | Stale picks after a killed reparse | Left as is: picks show only while their readings are offered, and the next reparse clears them (DESIGNS). |
