# M2.21b Links past 1,000 in a table of their own

## Built
1. **Table (cache schema 9, index checks 11).** `page_annotation (path, page_index, data, more, why, words)`, a rowid table with the primary key `(path, page_index)`: one row for each page that holds an annotation or has some left out. The key is the file's path, not the page key: an appended highlight changes no page key, and `#p.N` targets belong to the file. `saveIndex` strips the annotations from the facts and writes the rows in the transaction of the file's entry; `saveEntry` and `forgetEntry` delete the old rows; `dropUnused` (so `rm`, `gc`, `doctor --clean`) deletes rows whose path has no entry. Dry-run counts are unchanged. Every file's facts are read again after the upgrade (index checks 10 to 11), as for schema 8; the migration only adds the table.
2. **Caps, all with a trace.** 1,000 links and as many other annotations a page; 100,000 of each kind in a file; 512 KB of text on a page and 32 MB in a file; an annotation that several pages list is kept once. `FileFacts.moreOnPage` / `whyOnPage` carry the count and the cap's bits; `pdf read` ends a page that left some out with one line, `[10 more annotations on this page, past 1.0k links and as many others, not shown]`, other reasons named the same way, and a paragraph's own `[N more annotations here, not shown]` takes it on its line instead of a second one.
3. **Words under links, read when the page is read.** The facts no longer select them. `pdf read` asks `AnnotationWords.fill` for the pages of its chunk whose row says `words = 0`; one `__worker words` process (time and memory limits of the crop worker) selects the words under each link's box, and `Store.saveWords` writes them once, only while the file is still the version asked about. Marks (highlights and the like) keep their words in the facts, for the first 5,000 of a file, by count and with no clock.
4. **Links with no words.** A link to a page of the file with no words under it is counted in the page's line, not shown (`N links to pages of the file with no words under them, not shown`); a link to a web address stays for its address.
5. `Store.facts(olderChecks:)` lets the library `search` take section names from an older entry's facts when the file's stat matches; `FileFacts` decodes facts that lack the newer keys. `pdf ls` says "pdf was updated, read it again" for an entry the file still matches.

## Review findings
| # | Finding | Resolution |
|---|---|---|
| M1 | First read of a link-heavy file 3 s slower: words for every link in the facts. | Words read per page, in a worker, at the read. PGF first read 1.85 s. |
| M2 | Words depended on machine load; wordless links rendered as bare blocks. | Words by page, no clock (marks by count); wordless links to pages are counted in the page line, web links stay. |
| M3 | A 21 KB file filled the cache with 37.6 MB. | An annotation is listed once per file; bytes capped per page and file; reasons named. 2.2 KB now. |
| L1 | `ls` said "changed since it was read" after the upgrade. | "pdf was updated, read it again" when `hasEntry`. |
| L2 | Library `search` lost bookmarks after the upgrade. | `facts(olderChecks:)`. |
| L3 | Wrong reason at the file cap; shared cap let links crowd out comments. | Reasons as bits; file cap per kind. |
| L4 | Two "more" lines on a page. | Merged into the paragraph's line. |
| L5 | WITHOUT ROWID took 6.5 MB for 4.4 MB. | Rowid table. |
| L6 | FEATURES said `pdf info` counts them all. | Says it counts those left out. |
| L7 | No migration test or file-cap test. | Added. `dump --refs` lacks link DOIs: not a one-line fix, recorded in plan/TODO.md. |

Not done: a reparse does not touch the rows (they belong to the file's version, not to a page's parse).
