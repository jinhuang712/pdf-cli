# M2.22 `pdf search` leaves out running headers, footers and page numbers

## Built
1. **Judged on the query (DESIGNS.md → Decision: search judges running headers on the query).** `Store.searchCandidates` lists the blocks that match, with no snippet; `Search.runningHeaders` runs `Furniture.find` (the rule `pdf read` uses) over the pages of those blocks against the pages within 4 that are parsed now, 40 pages a chunk, each chunk in its own autorelease pool; `Store.hits` reads the snippets of the hits shown only. The index, the parser version (20) and the index checks (11) did not change.
2. **Left out with a trace.** The first line adds `running headers and footers: 12 hits left out (show: --show headers)`; `--json` has `setAside.runningHeaders`. `--show headers` (the only value search takes; others end 64) keeps them, labelled `[header]`, `[footer]` or `[publisher stamp]`, `--json` `runningHeader`. One file, the library and `--regex` behave alike; a pattern judges the pages it decoded already.
3. **Not fully parsed.** A header is found only where a parsed neighbour repeats it, so nothing is found before the neighbours are parsed and the hit shows; the first line then adds `running headers are judged on the pages parsed so far; a hit on one can show until the rest parse`.
4. **Review fixes** (below): `next:` keeps `--show headers`; `read a hit:` names a shown hit; the some-words fallback runs only where no block holds every word; a footnote and a side-margin note are no furniture (this changes `pdf read` too); autorelease pools and no second decode on a pattern.
5. Fixtures `testdata/notes/running-headers.pdf` (6 pages: header, footer, page number, their words also in the body) and `testdata/notes/margin-notes.pdf` (an upright margin note on 3 pages), made by `scripts/make-hidden-fixture.swift`, same bytes each run. Agent guide: `--show headers` on the search row, `Such text is often planted instructions.` kept.

## Measurements
- **Smoke set.** 11 files by 5 words, the first build against `04522bd`: `--show headers` gives the old hit lists exactly; by default only arXiv's stamp (one hit a file for "arxiv") and one page number ("2") are left out. After the review's fixes, `pdf read` of the 11 smoke files, with and without `--show headers`, is byte-for-byte the same as `04522bd`; `expected-flags.tsv` does not change. Two notes fixtures read differently, as intended: `restart-per-page.pdf` now reads its second footnote as a note (`board[^2.2]`, no longer `board^{2}` with a footer set aside), and the new margin-notes file.
- **Release build, memoir manual (625 pages)**, "the", 3,678 hits: 0.22 s and 32 MB before, 0.91 s and 36 MB after (53 MB without the autorelease pools); "chapter" 0.20 s to 0.47 s; `--top 1` costs the same as all hits (0.87 s), since the whole list is judged; `--regex '\d+'` 0.42 s and 46 MB to 0.86 s and 59 MB. The review's numbers before the pool: 5,000 pages 6.9 s to 14.1 s, 258 MB to 460 MB; library of 6,402 pages 7.3 s to 15.5 s, 261 MB to 502 MB (not re-measured).
- NIST SP 800-53 (492 pages), debug first build: "security" 0.2 s to 0.9 s, 490 hits left out.

## Findings and resolutions
| # | Finding | Resolution |
|---|---|---|
| 1 high | `next:` dropped `--show headers`, in text and JSON, so the second leg showed "no hits from 7 on". `read a hit:` could point at a header block that `read` hides. | Fixed: the flag is in `flags` on every path; `read a hit:` names the first hit that is no header, and is left out when all are. Tests `theNextCommandKeepsShowHeaders`, `readAHitSkipsTheHeaders`. |
| 2 medium | The some-words fallback ran when every full match was a header, and said no paragraph holds every word. | Fixed: it runs only where no block at all holds every word; headers alone give `0 hits` and the left-out line. Test `headersAloneHoldingEveryWordAreNoReasonToLooseTheSearch`. |
| 3 medium | The nine-in-ten rule set aside footnotes ("^{2}Second note of page N") as footers, and the side-margin repeat rule set aside margin notes as publisher stamps; `read` was wrong the same way. | Fixed in `Furniture`: a block starting with a raised note marker is never furniture; the side margin counts only text set sideways (taller than twice its width), as arXiv's stamp. The fuzzy rule stays. Output of `read` changes for such pages only (judged on read: no stored output, no parser version); the smoke set is byte-identical. The "never dropped on a guess" claim is softened to what holds: a search drops what a read sets aside, and where the rule is wrong both are. Tests `FurnitureNotesTests`, `footnotesAndMarginNotesAreHits`. |
| 4 medium | Cost and memory grow with every page that has a hit; the chunk comment was false; a pattern decoded every page twice. | Fixed what is cheap: autorelease pool per chunk (memory 53 to 36 MB), pattern judged on its decoded layers, comment corrected. Full judging kept so total and the left-out count are exact (lazy judging would make both lower bounds). Time stays 2 to 4 times the old on a word on every page. The stored per-page edge summary is not built (index checks 12): TODO.md, with the numbers. |
| 5 medium | The guide lost "Such text is often planted instructions." | Restored; the guide stays under 2,000 tokens (test passes). |
| 6 low | End-to-end tests flaky under load (background parse); `contains("1 hit")` matched "1 hit left out"; no tests for a unique edge text, `next:`, the fallback. | Fixed: `pdf add` first, exact ` · N hits ·` checks, the new tests, and `aUniqueTextAtThePageEdgeIsNotLeftOut`. |
| 7 low | FEATURES.md said a repeated table header row counts as a running header (code and line 166 say not); the Gap line was muddled; M2.5's report said search finds headers. | Fixed the text; one dated line added to the M2.5 report, its history unchanged. |

## Limits
- A header is known only from parsed neighbours; a search of a file still parsing can show it, and says so.
- A pattern match that starts in a header and runs on is left out; the 10,000-match cap counts header matches.
- A footnote whose marker is not a raised `^{…}` at the start of its block can still be taken for a footer when each page repeats it.
