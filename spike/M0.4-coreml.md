Date: 2026-10-14. Machine: Apple M3, 24 GB, macOS 26.4, Command Line Tools only (no Xcode).

The first run used random weights because the agent's network could not reach huggingface.co. All results below use the **real weights**, read offline from the local Hugging Face cache (`HF_HUB_OFFLINE=1`):

|---|---|---|---|

## Answer

- **Both models convert to Core ML** (mlprogram, fixed 1×3×640×640 input). Post-processing runs in Python.
- **Correctness:**
  - **fp32 is exact on every compute unit.** Every detection with score ≥ 0.5 matches PyTorch (same label, IoU > 0.9) on all 6 test pages.
  - **Plain fp16 is not safe on CPU or Neural Engine.** It matches only on GPU. On heron with ALL or CPU_AND_NE, only 3–6 regions per page still match.
  - **Mixed precision is nearly exact and fastest.** This means fp16 for the backbone and encoder and fp32 for the decoder, with compute units = ALL. It misses 1 of 107 heron regions and 1 of 67 egret regions.
- **Recommended setups:**
  - **heron, mixed precision, ALL:** about 23–29 ms per page.
  - **egret, mixed precision, ALL:** about 15–27 ms per page.
  - **egret, fp32 on GPU:** about 33 ms per page, if exact numbers matter.
- **Mixed precision under CPU_AND_NE gives wrong results.** Use ALL.
- **egret's wrong class scores on CPU were a Core ML bug, now fixed.** The bug persisted with real weights. The cause: Core ML's CPU backend returns wrong values for `x[:, -1]` on a size-1 axis, which D-FINE uses to pick its last-layer logits. After the fix (reshape instead of select), egret fp32 is exact on CPU too.
- **Swift without Xcode works:**
  - `MLModel.compileModel(at:)` takes 110–130 ms, then the model loads and predicts.
  - On a real page, Swift outputs match PyTorch: 9 of 9 detections for fp32 and for both mixed-precision models.
  - `xcrun coremlcompiler` is unavailable, and not needed.
- **Licences:** confirmed `license: apache-2.0` in both cached model cards (README front matter).

## What failed and the fixes (scripts in `spike/coreml/`)

1. **numpy 2.5 breaks the coremltools 9.0 `int` op** (`only 0-dimensional arrays…`). Fix: pin numpy 2.3.5.
2. **Sine position embedding** (`outer … int32 vs fp32`). Fix: precompute it as a constant.
3. **Runtime anchors** (an in-place copy shape error). Fix: set `anchor_image_size=[640,640]`, which gives the same anchors.
4. **Traced spatial-shape ints in deformable attention.** Fix: replace them with constants. grid_sample converts fine.
5. **D-FINE `F.linear` with a 1-D weight** (`AssertionError`). Fix: use the equivalent multiply-and-sum.
6. **D-FINE `logits[:, -1]` over a size-1 layer axis computes wrong on the Core ML CPU backend.** Fix: reshape instead. The bug was found with `probe_egret_cpu.py`.
7. **The `torch.export` path fails** on a data-dependent check. I used `torch.jit.trace`.
